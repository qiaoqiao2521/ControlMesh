# CM 基于 Paperclip 的改进方向

## Goal
将 CM 后续方向收敛为 Paperclip 基础上的改进版，优先复用原生任务、依赖、派发和唤醒，保留 CM 有实际价值的飞书/群聊与交付能力。

## User confirmation
2026-09-30 用户在完成真实 CLI 实验后明确要求“记录在 cm specmesh”，并表示 CM 以后成为该仓库的改进版。此处“该仓库”指 Paperclip。该确认取代 Orca 作为默认未来底座的选择；旧实现与验收资料保留。

## Requirements
- 纯 CLI 是必需路径；Codex 协调真实 AGY、ZCode、CBC 等现有 CLI。
- 派发后协调模型结束本轮推理，由执行系统等待；结果交齐后原生事件唤醒 Codex 独立审批。
- SpecMesh 交接当前目标、约束、结果和证据；尽量续接原会话。
- 任务交接完成、模型进程成功、产品通过验收分别判断；允许有依据拒绝与停止。
- 用户只收到有意义的结果、异常或需判断的分歧；不增加多份重复运维消息。

## Non-goals
本次记录不创建新 fork、不迁移生产 CM、不部署飞书、不删除 Orca/TS 候选，也不另造通用调度器。具体上游补丁、插件或 fork 布局按真实缺口再选；先保持现有生产入口。

- [x] 将用户选择写入 CM 项目入口、决策和计划，标明旧 Orca 优先级已被取代。

## Success and boundaries
本次已完成方向记录与本地CLI实验；不等于新CM产品、飞书投递或生产切换已完成。真实重启/回报丢失/多机等恢复需要各自证据。具体事实与来源见 findings，唯一下一步见 progress。
