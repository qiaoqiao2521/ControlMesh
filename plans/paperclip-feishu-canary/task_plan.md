# Paperclip 飞书本机接入与小服务器替换

## Goal
按2026-09-30用户新授权：先接通本机Paperclip飞书插件，确认创建/复用机器人能力；再选一台约4GB真实服务器替换一个既有CM入口，测量资源并关闭被替代的重复进程。

## Scope
本地现有lark-cli与Paperclip；最多两台候选只读比较，最终一台切换。复用已选入口身份；不删除旧运行态。保留可执行回退。用户已授权真实替换与必要停服务，无需重复询问整体部署许可；确需扫码/指定消息目标时再请求具体输入。

## Steps
1. 核实插件源码、安装接口、当前CLI身份与机器人创建/复用路径。
2. 安装本地插件并验证API配置、事件监听与授权消息闭环。
3. 选定4GB候选，检查现有服务、任务、内存、磁盘与身份，确定单一消息消费者。
4. 安装备份与候选，停被替代的重复入口，切换一个真实机器人，检查收发/任务/交付。
5. 记录峰值/空闲资源、回退命令和实际验收边界。

## Success
插件与CLI实际兼容；创建/复用能力有源码或命令依据；单一服务器新入口收发与任务响应可验证；旧入口不并行消费消息；资源统计说明测量窗口。真实消息/权限缺口不冒充完成。

## Current
本机复用与真实收发/模型交付完成；兼容版已默认去噪。greenrise部署/重启/资源和实际CLI调用已测；旧CM入口接管未通过，暂保留。当前结论和接续步骤见progress.md。
