# Architecture

## 默认产品与边界

默认入口运行锁定版本的 T3 Code Server/Web。`npm start` 直接使用上游启动器；`cm` 和 `cm t3 ...` 透明转交同一运行时。版本与来源见 [t3-upstream.json](../t3-upstream.json)，安装和首次下载见 [installation](installation.md)。CM 不另建会话、调度、认证或记忆数据库。

| 组件 | 拥有的行为 | 边界 |
| --- | --- | --- |
| T3 Code | 界面、线程、执行器、远程连接、Git、检查点和运行状态 | 上游回合结束不代表业务验收或产物交付 |
| `controlmesh.t3` | 解析明确的运行时路径，转交参数、输入输出、退出码和信号 | 不复制线程，不猜测认证，不自动重试；退出码本身不是验收结果 |
| `controlmesh.verify` | 检查已有产物，运行显式检查，绑定源码状态，按需核对远端提交 | 不调用 Agent，不提交或推送，不推断未覆盖需求 |
| TraceMesh | 记忆存储、召回、维护、宿主注入，以及历史轨迹压缩、提纯和缺口检索 | 独立维护插件；宿主直接使用，CM 不设调用代理、注入参数或回执转发 |
| SpecMesh | 项目意图、约束、职责与渐进索引；必要的交接材料 | 普通任务不必生成交接包或加载全部资料 |
| 兼容工具 | `run` 执行外部命令；`workflow` 组合 SpecMesh；`closeout` 同步明确段落 | 仅显式调用，均不承担默认 T3 会话运行 |

T3 保留其原生持久状态。这里精简的是重复实现，不删除上游恢复、权限和工作区隔离能力。飞书为目标生产入口；本轮源码改造不等于飞书或真实模型端到端验通。

## 从执行到交付

T3 中的主 Agent 接收需求、使用原生工具和按需分工，再按任务要求调用 [独立验收](verify.md)。报告记录检查命令、产物和源码身份；有交付要求时额外观察远端分支。主 Agent 根据实际结果，在已有授权范围内修复、接续或交付。

`thread start/send --wait --json` 的结果沿用 T3 原义。等待进程退出或超时不等于服务端任务取消；不因缺少回执重复派发。需要确认时读取原线程。项目 [t3.json](../t3.json) 提供可手动导入的动作，不是每轮自动执行的完成钩子。

`cm verify` 报告只证明指定检查与产物在该次源码观察中的结果。源码变化后旧报告保留历史价值，不能直接作为新版本验收；忽略文件、子模块内部和真实部署另有覆盖边界。工具沿用调用方权限，不提供额外操作系统沙箱。

## 记忆归属与历史实现

记忆直接归 [TraceMesh 插件](https://github.com/qiaoqiao2521/AgentTraceMesh/blob/main/docs/memory-plugin.md)，其源码、测试、许可与维护记录在独立仓库。DSH 插件按需安装到原生宿主，与 CM 的 Python 包和 CI 无依赖关系；CM 不设 `context` 代理、记忆注入或回执转发。插件代码迁移沿用原数据目录、companion 身份和记录格式，不表示已经替换用户机器上的安装。

陪伴插件在 CM 中的历史来源，以及已退役的 Codex 专有回调与派发 Skill，见 [历史索引](retired-components.md)。0.44.0 的执行工具沿用为兼容能力。源码退役不迁移服务器，也不删除私人数据。当前实际验证以 [本轮进度](../plans/t3-primary-20261126/progress.md) 为准。
