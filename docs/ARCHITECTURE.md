# Architecture

## 当前执行路径

调用方明确任务与命令；`cm run` 执行一次，再运行显式检查，检查选定产物，写 JSON 报告。当前宿主读取报告与产物，继续修复、交付或说明具体阻碍。所有步骤在调用时发生，无后台调度数据库。

| 模块 | 拥有的行为 | 不推导的事实 |
| --- | --- | --- |
| `controlmesh.execution` | 子进程执行、共用超时预算、日志、显式检查、产物摘要、接续建议 | 业务需求是否全面满足、允许扩大权限、是否应自动重试 |
| `controlmesh.workflow` | 组合独立 SpecMesh 导出与消费前核验，保留原 JSON | 材料可读不等于完成或授权 |
| `controlmesh.closeout` | 读取已提交段落、检查并同步显式目标管理区 | 不自动判定业务状态、不提交或推送 |
| 当前宿主与所选 CLI | 工具、登录、模型、权限、原生会话、任务判断 | 一个 CLI 成功不代表其他 CLI 可用 |
| 可选 `vendor/codex_callback` | 已绑定原 Codex 线程的作业完成通知与回执 | 送达不等于产物通过；历史连通不等于今天连通 |
| 可选 DSH 插件 | 个人陪伴记忆保存与召回 | 不充当项目权威或通用运行时 |

`cm` 与 `python3 -m controlmesh` 是核心入口。标准库工具可在 `python3 -S` 下运行；可选插件和外部工具的依赖单独安装。

## 执行报告边界

报告含执行结果、每个验收命令的结果、所选产物和下一步建议。报告路径必须是新文件，旁边的独立日志目录保存本轮输出；运行记录应放到私有目录。

任务文件只记录身份与关联，不被自动拼入执行命令。`--artifact` 约束验收目标，不限制命令对文件系统的访问。命令使用调用方权限，CM 不提供额外沙箱。

超时预算覆盖执行和检查。执行或验收失败保留实际输出，报告不会重试原命令。已有授权允许继续修复时，宿主依据事实自主接续；更换方案和权限由当前任务约束决定。

可选的前次报告比较要求同一工作目录、任务内容和验收约定。比较用于发现同类失败或无进展，不声称理解任务全部语义，也不自动启动另一执行者。

## 项目连续性

SpecMesh 保存当前任务意图、约束和代码职责；TraceMesh 检索原始历史证据；CapMesh 保存能力取舍。按本次任务选择材料，避免让每位 worker 重读整段历史。需要交接时生成并核验材料，正常本机小任务直接使用原记录。
