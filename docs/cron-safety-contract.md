# Cron 失败收敛与磁盘有界规范

状态：2026-10-09 用户批准的规范；本次仅文档与模板，**未实现、未部署、未通过运行故障注入**。
CM 是 Paperclip 的薄适配层。Paperclip 仍拥有 routine、时钟、issue/run 生命周期和事件唤醒；
本规范约束任务执行准入、资源预算和交付，不创建第二个调度器，不修改上游核心。

## 适用入口与现有证据

- 新任务或修改任务先填写[任务契约模板](templates/cron-task-contract.md)，与任务源码同仓审查；模板不是运行配置或可直接导入的 API payload。
- 当前薄适配为 [cm-process-runner](../scripts/paperclip/cm-process-runner)：
  `resolve_native_issue` / `resolve_routine_job` 校验原生归属与 `cmJobId`；
  `execute_cron_job` 执行旧任务的一次性命令；`run_owned_process` / `kill_owned` 处理限时和所属子进程。
  这些接点仅是后续实施位置，不表示本规范的预检、熔断、去重与配额已经存在。
- [已有迁移证据](../plans/fleet-paperclip-agy-20261001/findings.md)记录
  `skip_if_active`、Agent `maxConcurrentRuns=1`、`skip_missed`；部署时必须回读目标版本，不能用历史记录代替当前配置。
- [旧 Python cron 模块](modules/cron.md)为历史实现资料；不得为采用此规范恢复旧 daemon、旧 consumer 或已退役环境。
- 任务说明里的“不要调用模型”不足以保证零模型：确定性准入必须发生在 provider/Agent 启动前。
  若选定原生入口只能先启动模型，标为不符合规范，等待另行实现薄适配，不用提示词冒充门禁。

## 1. 执行前置条件

为每项任务显式声明：稳定任务 ID、仓库与版本、所有者、输入路径/来源、必需格式、
输入新鲜度、工作目录、输出清单、幂等键、截止时间和磁盘预算。
以确定性代码校验输入存在、可读、非空、格式/版本正确、时效有效、路径在允许根目录内，
以及可写目标和足够配额。不能只验证父目录存在；不能自动回退旧日期输入或创建空源文件掩盖缺失。
跨天目录应由明确业务日期/时区规则解析，不硬编码历史日期。
预检失败不得调用模型、生成补丁/overlay、派生修复 Agent、追加长 MEMORY 或复制全量备份。
权限/认证失败不得换身份或放宽安全设置。预检本身须有超时和输出上限。

## 2. 错误分类与有界重试

| 类别 | 例子 | 规定 |
|---|---|---|
| 永久/需人工修复 | 必需源不存在、配置/格式错误、权限拒绝、身份无效 | 进入持久 `blocked` 诊断状态；禁止自动业务重试、模型、补丁；后续 tick 仅作廉价预检及计数 |
| 临时且可证明重试安全 | 网络超时、明确限流、短时依赖不可用 | 同一故障事件最多 **3 次重试（首次 + 3 = 最多4次尝试）**，默认退避30/120/600秒，有限抖动，遵守更长的 Retry-After |
| 未知或结果不确定 | 写操作超时、发送ACK丢失、进程崩溃后结果未知 | 不猜测成功或自动重放；持久 blocked，先核对幂等回执和产物 |

重试预算按稳定任务 ID + 故障事件持久化，不能因新 tick、进程重启或新 issue 清零。
退避/等待只使用原生拥有者支持的机制；无对应能力时下一次正常 tick 检查 `next_eligible_at`，不另建时钟，不让模型轮询。
达到3次重试后 blocked；不得每轮重开一组3次尝试。长期 Retry-After 超出任务期限时直接 blocked。
连续失败计数、抑制次数和最近失败时间保存在固定大小状态中，不把每次失败写成新文件/新评论。
这里的状态名/字段是任务诊断契约，不是新 Paperclip 状态枚举或未经验证的 API 字段；
原生 issue/run 仍通过目标版本已有、已校验身份的接口回报实际状态。

## 3. 单实例、超时与原子状态

- 对稳定任务 ID 取得非阻塞单实例锁，覆盖预检、业务执行、输出提交与状态变更。
  相同任务的重复 tick/恢复试跑共用锁；冲突只计 `skipped_active`，不排队补跑、不启动第二个模型。
- 复用原生单实例语义并核对；同机任务可用进程退出自动释放的 OS 文件锁。
  多机同一写目标必须有明确唯一 owner/受支持共享锁；不能假装本地锁能防跨机重复。
- 总执行超时默认600秒，含预检/业务/校验；任务可经审查设更小预算。
  超时或取消先终止所属子进程，宽限默认5秒后强制回收并等待退出。
  只回收验证归属的进程树，不按名字批量kill、不杀共享进程组；无法证明已回收则保持 blocked。
- 状态至少表达：任务ID、契约版本、诊断状态、错误指纹、首次/最近失败时间、失败/抑制计数、
  重试次数/下次可尝试时间、输入版本、最后成功产物摘要、通知事件与回执。
- 指纹由任务ID、稳定错误码、归一化输入标识、契约版本计算；排除时间戳、run ID、堆栈噪音和秘密。
  同因跨重启指纹相同；原因变化才产生新事件，不建立无限指纹历史。
- 在锁内以同目录临时文件写入、flush/fsync、原子rename并同步目录；校验大小与schema后替换。
  保持一个固定状态文件和至多一个临时文件，失败只清理本轮拥有的临时文件。
  状态损坏、磁盘写满或持久化失败时 fail closed：不运行业务，不反复发送无去重告警。
  计数使用有界整数并饱和，不因溢出恢复执行。

## 4. 通知与模型边界

故障通知仅在首次失败、稳定原因变化、已验收恢复时产生；同一原因的后续失败只更新计数。
每个事件具有稳定幂等键与持久回执，正常等待/抑制不发消息。通知沿已授权的任务交付渠道和身份，禁止 fan-out。
通知失败不会使业务自动重跑；若通道支持幂等键，可有限重试同一事件，否则发送结果不确定时标记待核对，不能盲重发。
“恰好一次”只在已验证幂等投递或ACK模型下承诺；断电发生在发送成功与本地ACK之间必须列入验收。
业务产物按原批准需求交付；本节抑制的是重复故障/运维消息，不取消已授权业务交付。
永久错误模型预算为0。修复需独立、明确授权的开发任务，不能由cron每轮复制补丁、派生Agent或换模型再试。
若业务本身需要子任务，必须在契约中给出有限数量/深度/总预算；缺省不派生，不允许子任务续造无限后代。

## 5. 日志、元数据与备份预算

| 对象 | 默认硬上限 | 写入规则 |
|---|---|---|
| 每任务日志（含stdout/stderr/堆栈/本地副本） | 合计20 MiB；最多5个文件（1活动+4轮转），每文件4 MiB；最多7天 | 流式截断单记录至16 KiB；写前轮转/淘汰该任务已受管日志，不能先无限写再靠日后清理 |
| 状态、通知去重/回执、临时状态、锁及故障索引 | 合计1 MiB、最多16个文件；单份状态≤64 KiB | 固定文件/有界环形记录，诊断详情最多7天；活动blocked状态及当前去重键保留到事件结束，不按7天失忆重复告警 |
| 代码/配置变更前备份 | 默认最近3份，合计默认30 MiB | 只在实际获准变更前生成，重复运行/失败不备份；超预算无法保留必要回滚时阻断变更并审阅预算，不能静默丢唯一副本 |
| MEMORY | 固定摘要默认≤64 KiB | 只记录决策/状态改变，不逐轮追加长文，不为追加生成全量副本 |
| 临时物料与正式产物 | 各任务必须声明字节、文件数、留存上限 | 未声明则不准入；本轮临时目录失败后有限回收，唯一成果不得按临时文件处理 |

20 MiB是所有任务日志副本的总预算，不是每个sink各20 MiB。实施前盘点进程输出、Paperclip run记录与系统日志；
高频重复错误不得原样扇出到journald/模型日志/原生评论中。无法控制的外部sink必须列为未通过项，不能宣称磁盘全局有界。
7天留存由现有原生拥有者的受管日志维护能力保证，任务长期静默时也必须覆盖到期处理；
若只有下次写入才轮转而没有到期能力，不得宣称严格7天已实现，也不得私建新清理时钟。
模板不会自动配置全局日志系统；调整生产日志策略、回收既有备份/历史都需另行授权。
新受管目录从一开始遵守限额，禁止规则追溯扫描并删除旧历史。备份与源码、唯一成果不得混作缓存。

## 6. 产物与恢复

exit 0不等于成功：核对预期文件完整、格式可解析、必要字段/校验和齐全，且业务日期、输入版本和生成时间满足契约。
先写本轮临时产物，验证后原子发布；旧产物不能冒充本轮，失败不得覆盖最后良好结果。
外部写入/交付先核实幂等回执；不确定状态禁止重复副作用。
源恢复后先在同一锁与幂等范围内**单次试跑**；仅预检恢复不清除故障、不发送恢复通知。
试跑通过完整性、新鲜度、进程退出和投递验证后才恢复正常准入、清零连续失败预算、发送一次恢复通知。
没有额外时钟/补跑消费者；生产时钟是否启停由原拥有者和单独授权决定。本规范不授权启用暂停任务。

## 7. 可执行验收清单（后续实施必须提供真实证据）

在临时隔离夹具中模拟输入、时钟、通知接收器、provider启动和补丁写入计数；不调用真实模型/飞书，不读用户秘密。
按相同生产准入入口触发，记录源码版本、入口、配置、计数、峰值字节数/文件数和回执；不能只测试复制出来的伪状态机。

| 故障注入 | 必须断言 |
|---|---|
| 必需源缺失，连续100次tick（含中途进程重启） | `blocked`；失败计数100；模型0、补丁0、每轮备份0；确定投递成功的接收器仅1条首次通知；不生成长MEMORY/派生脚本/Agent；状态不因重启丢失 |
| 相同原因堆栈/时间戳改变 | 指纹不变、无新增通知；真正原因改变才新增1条 |
| 临时网络错误、跨tick/重启 | 首次+最多3次重试；30/120/600秒退避和期限生效；耗尽后不再执行 |
| 两个同时触发及手动恢复与tick竞争 | 业务最大并发1；幂等副作用最多1次，不排队追赶 |
| 子进程挂起/取消/TERM后派生子进程 | 总超时+宽限内收口，所属后代无残留；无法确认则blocked；其他任务进程未受影响 |
| 状态写一半崩溃/写满/通知成功后ACK丢失 | 旧或新状态完整，禁止半JSON；不丢重试预算、不重复副作用；通知不确定可见且无盲重发 |
| 大量stdout/stderr/频繁原因变化、推进8天 | 任一时刻日志≤20 MiB且≤5文件、受管日志≤7天；元数据≤1 MiB且≤16文件；MEMORY≤64 KiB；额外sink计入测量；不触碰旧历史 |
| 输入恢复但产物为空/陈旧/格式错误 | 不报成功，不恢复准入，不发恢复通知 |
| 输入修好且单次试跑通过 | 只执行一次，正常准入恢复，恰好1条恢复通知；下一tick不会重放已完成副作用 |
| 无代码变化重复100次；随后4次获准小变更 | 前100次备份0；新受管备份最多3份/30 MiB；既有历史与唯一成果未删除 |

验收记录分别填写“规范已审阅”“离线适配测试已过”“目标部署回读已过”“实际业务/交付已过”。
