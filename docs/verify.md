# 核验已有结果

`cm verify` 在 T3 执行后检查已有文件和显式检查命令，不再次启动 Agent，也不重新执行生成任务。当前要求 Linux、Python 3.11+ 和 Git。主 Agent 选择能观察实际要求的检查，并按已有授权处理结果。

## 一次验收

先创建私有报告父目录，替换下面的项目、检查与产物路径：

```sh
cm verify --cwd /absolute/project \
  --report /absolute/private-output/verify-001.json \
  --verify 'python3 check_result.py' \
  --artifact result.txt \
  --timeout 900
```

未安装 Python 包时，从 CM checkout 使用 `python3 -B -S -m controlmesh.verify` 替代 `cm verify`。`--verify`、`--artifact` 都可重复；每次使用新报告路径，执行检查和观察状态共用超时预算。`--cwd` 是实际检查工作目录。

检查字符串解析为 argv，以 `shell=False` 执行，不自动展开管道、重定向或变量。仅传入已明确选择、可信的检查命令；确需 shell 时显式指定并正确引用。工具沿用调用方权限，产物清单不是沙箱。

## 状态

| 状态 | 退出码 | 含义 |
| --- | --- | --- |
| `verified` | 0 | 至少提供一项检查且全部通过，声明产物齐全，覆盖内的源码在检查期间保持一致；请求的远端证明也满足条件 |
| `needs_repair` | 1 | 检查失败、产物缺失、清理失败，或已确认提交不在指定远端分支 |
| 参数错误 | 2 | 输入无效；不能当作任务已经执行或业务失败 |
| `unverified` | 3 | 没有检查、工具不可用、源码观察不完整或已变化，或交付证明不足 |
| `timed_out` | 124 | 本次检查和观察超过预算 |
| `interrupted` | 128 + signal | 本次验收被中断，需读取已有结果后接续 |

只找到文件或收到 T3 的完成回复仍然是未验收。检查报告的 `verification`、`artifacts`、`source` 和按需生成的 `delivery`；`next_action` 是建议，不是额外批准或自动重试。

## 证明代码已到远端

在需要核对交付的那次验收中增加：

```sh
cm verify --cwd /absolute/project \
  --report /absolute/private-output/delivery-001.json \
  --verify 'python3 check_result.py' \
  --artifact result.txt \
  --commit HEAD --remote origin --branch main
```

它分别记录本地提交是否存在、实际观察到的远端分支、远端是否包含该提交，以及该提交是否对应本次检查的源码。缓存的 `origin/main` 不作为远端已收到的证据；工具不 push、不修改远端。

远端已前进而本地缺少必要对象时，结果保留为未确认；按事实获取该分支后重新核对，不把缺少证据判成未交付。要将检查与一个已推送提交绑定，需要检查期间源码稳定、工作区干净，且指定提交就是被检查的 HEAD。普通未提交工作区仍可检查，但不能据此声称某个提交已通过并交付。

## 证据范围与新鲜度

报告绑定项目身份、实际工作目录、Git 提交和覆盖内的源码内容。跟踪文件读取磁盘实际字节、文件模式与符号链接目标，不只依赖 `git status`；未提交或未忽略的新文件也会影响证据。检查过程中源码变化后，成功的命令退出也不会成为新鲜的通过结论。没有可观察 Git 工作区、或稀疏检出缺少需要观察的跟踪文件时，即使检查通过仍保持 `unverified`。

Git 观察子进程从原始 `--cwd` 定位仓库，清理会重定向仓库的环境变量，并禁用 `replace` 和 `graft` 历史替换。它不修改用户 Git 配置；实际检查命令仍继承调用方环境，因此这些措施不构成执行沙箱。

交付证明还要求磁盘上的原始跟踪内容与 Git 索引中的对象匹配。使用 `clean`/`smudge` 过滤器或换行转换时，工作区字节可能不同于提交内容；本版对此保守处理，即使 `git status` 看起来干净，也不会直接认定它就是已推送提交的验收结果。工作区行为仍可单独检查，转换后内容与提交的对应关系需要额外证据。

当前覆盖不包含 Git 忽略文件、子模块内部的完整内容，也不自动覆盖运行环境、视觉效果或真实部署。声明产物的存在和摘要由 `artifacts` 单独记录，正确性仍由具体检查决定。报告是该次观察的证据；以后代码再变化，旧报告不能直接证明新版本。

报告和日志放在私有目录，使用新路径、受限权限并原子发布。运行日志可能含工具输出，不提交报告或日志到仓库。只为尚未覆盖的实际风险补检查，不要求每次任务重跑整套无关测试。
