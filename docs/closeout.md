# 任务收尾：一个 CLI，两个动作

```bash
cm-closeout check
cm-closeout sync
```

默认配置是 `~/.config/controlmesh/closeout.json`；首次将
[示例](closeout.example.json) 的两个路径改为自己的 Git 仓库根目录。
另一个配置可用 `--config /path/to/closeout.json`。一个配置可列多条显式关系，
不要求每仓配置，也不要求安装 Agent。实现属于 CM，不修改 SpecMesh 公共标准。

`check` 只读，列出待同步或阻塞；一致时只说“已一致”。`sync` 先检查全部关系，
再更新各目标的管理区域；未知、冲突或来源未提交时停止。退出码：0 一致或同步成功，
1 待同步，2 阻塞。没有模型调用、后台监听、定时任务、自动 hook、联网拉取或任意命令配置。

任务收尾者先更新并提交来源状态，执行 check/sync，然后查看接收仓 diff、提交并推送
有效变更。脚本不负责判断任务是否值得继续，不自动 add/commit/push 混合工作区。
来源提交应一并推送；CLI 离线读取本地 HEAD，不声称检查了远端是否收到。

## 同步什么

首条关系将 CM 当前计划中的 `## Current` 复制到 CapMesh 的状态引用。
能力表和 PROJECT 指向这一处引用，避免各自维护一遍“本机通过、生产未通过”。
其他仓只在出现明确接收需求时增加一条关系。

- 来源：已提交且工作区干净的 Markdown 文档中唯一的二级标题正文。
- 目标：首次只能新建文件；后续只写 `cm-closeout` 标记围住的区域，区域外字节保留。
  现有无标记文件、手改区域、重复标记均拒绝；先保留人工修改，再由维护者明确解决，
  没有 force 覆盖选项。
- 链接：普通行内链接相对来源路径解析，固定到来源 GitHub 提交；来源须配置 GitHub origin。
  支持正文/列表/简单行内链接；复杂 Markdown（代码块、HTML、引用链接、带空格或嵌套括号链接）
  明确拒绝。来源与链接不经过模型改写。
- 去噪：只对选定段落、来源位置与仓库身份做摘要；无关 HEAD 变化不刷新既有引用。
  标记内摘要同时检查人工改动。删除规则不自动删除既有产物。

每个目标文件只允许一个同步关系，单次不支持目标再作为另一条来源。
全部预检通过才开始写；每个文件临时写入后原子替换。中途失败可能已完成前几项，
会明确报告数量，重跑幂等继续；这不是跨仓事务。
CLI 实例之间用仓库锁串行；写入前后检查目标变化。
普通编辑器不遵守这个锁，文件系统没有“比较内容并替换”的通用原子操作，
因此沿用单个收尾者约定，不与其他 Agent 同时编辑管理区域。

## 依赖与验证

当前面向 Linux/macOS，Python 3.11+、Git 和标准库即可。安装 CM 后包含 `cm-closeout`；
尚未安装 CM 时，在源码根目录运行同一入口：

```bash
python3 -S -m controlmesh.closeout check --config /path/to/closeout.json
```

`-S` 禁用第三方 site-packages，仍能运行，不会导入 provider/runtime。
测试用临时 Git 仓库覆盖来源变化、幂等、手改冲突、并发修改及路径边界：
`pytest tests/test_closeout.py`。真实同步只证明引用一致，产品、部署和人工验收继续回源。
