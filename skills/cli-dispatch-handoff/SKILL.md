# CLI 后台派发与交接

任务要求严格、交接索引详细；执行只做“探测 → 派发 → 让出会话 → 回调验收”。
本 Skill 不建立调度器、账号层、模型代理或后台轮询服务。

## 派发

1. 沿用项目已有计划，写明目标、输入来源、允许修改范围、不得修改项、逐项验收方法、交付目录、交接文件及停止条件。重要要求逐条编号，不能只写“做好一点”。小任务使用短任务文件即可。
2. 每批运行一次探测。默认顺序 Qoder → AGY，优先 `usable=true`；都未通过时仍按 `selected` 派发一次，保留 `degraded=true`。不反复测额度、不永久拉黑、不把未知状态说成可用。CBC 仅显式指定；DSH 暂停。
3. 正式任务沿用 CLI 已有登录、模型、网络和权限配置。**不要把 AGY 的探测用 plan 模式带入实现任务**；不自行添加跳过权限参数。
4. 复用当前已就绪的完成回调。Codex 外部后台结果走原线程 queue；已有 hcom 路由先确认其完成事件确实接回原会话，不能将 hcom ACK 当完成回调。新 CLI 进程优先复用仓库的 `codex_callback.start_job`。
5. 将任务编号、所选 CLI、原线程 ID、任务文件、交接文件、回调运行目录写入同一份派发索引。确认启动器已返回运行记录并绑定原会话，即可向用户报告“已派发，待回调验收”，**结束当前答复**。

## 派发后的行为

- 不等待开始渲染，不反复 `hcom listen`、查日志、查进程、数帧或循环读状态；不通过 sleep/wait 保持主会话占用。
- 不用同步 `agent-link.spawn_agent` 包住长后台任务再等待它返回。短同步读取、审查、计算仍可使用 agent-link。
- 同一任务只保留一个完成通知 owner；已有任务继续原会话，不重复启动任务或注册第二条回调。
- 用户主动问进度时，可做一次针对性查询；回调失败或明确异常时按原事件修复。这些例外不变成后台监控。

## 接续

收到回调后才读取交接和相关产物，按编号逐项核验。记录通过、未通过、未覆盖及事实依据；回执、退出 0、空 `done` 均不是业务验收。最后执行该项目要求的提交、临时产物清理和交付；保留可编辑工程与必要素材。

通道不可达时，保留任务文件并报告具体连接问题；不伪称会自动汇报，也不退回主会话持续轮询。额度双失败允许尝试，与回调通道可达是两件事。
